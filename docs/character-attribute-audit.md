# 角色属性审计报告

审计日期：2026-08-11  
审计范围：`characters` 表全部 13,373 名角色  
结论：本次仅审计与报告，未修改任何数据库或代码。

## 摘要

1. 13,373 名角色中，12,485 名为按 VNDB 原始数据导入的角色，属性与 VNDB 原始数据完全一致；其余 888 名为旧 `characters.json` 保留角色，共有 1,653 处字段差异，涉及 606 名角色。
2. 大量差异来自“聚合口径”而非事实错误：VNDB 一个角色会挂多部作品、多个发售版本、多组标签，首轮按单值重算时在作品名、会社、年份、发色上产生系统性偏差。
3. 发色是重点。按“仅发色 trait”重新比对后，142 个首轮发色差异中只有 13 个是真冲突、4 个是 VNDB 漏标；结合网络复核，确认数据库发色错误 5 个、疑似 5 个，其余多为数据库正确而 VNDB 标错或漏标。
4. 不建议整体用 VNDB traits 覆盖数据库；建议按本文档清单逐项人工确认后做最小化修改。

## 1. 数据与方法

### 1.1 数据源

- 当前数据库：`characters`（PostgreSQL），共 13,373 行；难度分布为 beginner 262、easy 502、normal 13,373。
- VNDB 原始数据：`vndb-db-2026-08-07/db/`（chars、chars_traits、traits、chars_vns、vn_titles、releases、releases_vn、releases_producers、producers、vn_seiyuu、staff_alias 等）。
- 旧数据：`server/data/characters.json`、`server/data/characterIds.json`。
- 网络资料：萌娘百科、百度百科、快懂百科、B 站、手办/商品页等。

### 1.2 比对方法

首轮：用与导入脚本相同口径从 VNDB 原始表重算 `cv / work / company / release_year / hair_color / hair_length`，逐项与数据库比较，输出 `/tmp/attribute-audit.tsv`（已复制到 `docs/character-attribute-audit.tsv`）。

修正：发色重新只取 VNDB“发色”trait 节点（Black、Blond、Brown、Blue、Pink、Violet、Red、White、Green、Teal、Grey、Claret、Orange），用集合判断数据库值是否落在其中，排除眼珠颜色。

网络：对难度池中受影响角色及 13 个真冲突角色逐一搜索复核。

### 1.3 首轮聚合口径的噪声

- 会社：VNDB 取全部发售版本中按名称排序最小的 developer，会选中移植商、汉化组、同人社团。例：魔法使之夜角色数据库为 `TYPE-MOON`，VNDB 聚合出 `HuneX`，HuneX 只是其中一个移植版 developer。
- 年份：VNDB 取全部 release 的最早年份，会选中先行体验版、移植版、汉化版。
- 作品：角色挂多部系列作品时 VNDB 只取其中一条，数据库保留旧数据里的“主作品”。
- 发色：首轮把眼珠颜色也当发色计算，且多标签时按固定顺序只取第一个。例：库·丘林数据库为蓝发，VNDB 原始发色标签也是 Blue，首轮却误报为红发（取自红瞳）。

## 3. 各字段结论

### 3.1 cv（548 处）

绝大多数是同一声优的写法差异：

- `井上麻里奈` vs `観村 咲子`（18 禁别名）
- `川上とも子` vs `川上 とも子`（空格）
- `田村ゆかり` vs `田村 ゆかり`（空格）

另有少量 VNDB 缺 CV 而数据库有值（如 神岸明：数据库 `日々野晴子`，VNDB 未知）。风险低，但无法批量判断，建议只对高优先级角色复核。

### 3.2 work（294 处）

主要是同一作品或系列的不同写法：

- `ef - a fairy tale of the two.` vs `悠久之翼`
- `月姬` vs `月姫`
- `CLANNAD` vs `CLANNAD - 被光守望着的坡道`
- `寒蝉鸣泣之时` vs `寒蝉鸣泣之时解`（系列作）
- `传颂之物 虚伪的假面` vs `传颂之物3：二人的白皇`（同一角色多部出场）

结论：需要先定义“主作品”口径，不能把 VNDB 多条关联当作错误覆盖。

### 3.3 company（270 处）

绝大多数是日英名、更名、别名：

- `Leaf` vs `AQUAPLUS`（同一会社更名）
- `August` vs `オーガスト`、`PALETTE` vs `ぱれっと`、`GIGA` vs `戯画`、`âge` vs `アージュ`、`Minato Soft` vs `みなとそふと`
- 魔法使之夜角色：数据库 `TYPE-MOON`，VNDB 聚合出 `HuneX`，原作/主要开发为 TYPE-MOON，数据库更准确。
- 月姬角色：数据库 `TYPE-MOON`，VNDB 聚合出 `フランスパン`（MELTY BLOOD 等衍生作的同人社团）。

结论：不建议按 VNDB 覆盖；个别角色可人工确认“主要开发会社”。

### 3.4 release_year（253 处）

大多是 VNDB 取最早 release 造成的：

- `2011 -> 2010`（69 处）、`2012 -> 2011`（24 处）
- `CLANNAD 2004 -> 2008`（全年龄版/其他版本）
- `2000 -> 1999` 等先行版

结论：数据库年份通常对应主作品首发，建议保留，除非逐条确认口径。

### 4.5 为什么不能整体覆盖 VNDB 发色

- VNDB 会同时挂多个发色：牧濑红莉栖 Brown+Red、向坂环 Red、藤香 Violet、能美 White、加藤羽未 Violet。
- VNDB 有漏标：天王寺绹等 4 人没有发色标签。
- VNDB 有明确标错：伊吹风子 Green、言峰绮礼 Brown、藤香 Violet、能美 White、加藤羽未 Violet 等。
- 首轮差异表混入了眼珠颜色，直接覆盖会把库·丘林（蓝发）改成红发、把伊莉雅（白发）改成红发等。
